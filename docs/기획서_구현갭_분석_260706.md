# 코디팝 기획서 vs 현재 구현 상태 분석

> 기준 문서: `코디팝 기획서_260706.docx`  
> 분석 일자: 2026-07-06  
> 대상 코드베이스: B2C 앱 (`CodiPop`) + Render 백엔드 (`codipop-backend`)

## 개요

기획서 방향은 **B2C 앱 → B2B 쇼핑몰 솔루션(플러그인/SDK)** 확장이다.  
기술 엔진(합성 속도·품질·모델 전환 구조)은 기획서 주장을 이미 뒷받침하지만, **B2B 레이어(SDK·자동 추출·대시보드)와 데이터 기반(로깅·인증)이 통째로 비어 있는 상태**다.

---

## 기획서 약속 vs 현재 구현 상태

| # | 기획서 내용 | 현재 상태 | 격차 |
|---|---|---|---|
| 1 | 사진 + **키/몸무게 입력** 기반 피팅 (#4) | 사진만 받음. 키/몸무게 입력 UI·저장·프롬프트 반영 전부 없음 | 신규 개발 |
| 2 | 3~10초 피팅 (#4) | 6.3초 실측, 충족 | 완료 |
| 3 | **AI 믹스매치 업셀링** — 피팅한 옷과 어울리는 상품 추천 + "함께 피팅" 유도 (#5-5) | 없음. `/get-recommendation`은 옷장 아이템·날씨가 **프롬프트에 하드코딩**돼 있어 사실상 데모 수준 | 고도화 필요 |
| 4 | **MD 대시보드** — 피팅 조합 통계, 잠재 선호 데이터 (#5-6) | 없음. 대시보드는커녕 **피팅 이벤트 로깅 자체가 없어서** 보여줄 데이터가 쌓이지 않는 상태 | 신규 개발 |
| 5 | **한 줄 스크립트(SDK) 연동** — 카페24/고도몰 등 (#6-Q1) | 없음. 웹에 삽입할 위젯/스크립트 없음 | 신규 개발 (B2B 핵심) |
| 6 | **상세페이지 이미지 자동 추출** — 누끼/재촬영 불필요 (#6-Q2) | 없음. 지금은 사용자가 갤러리에서 옷 사진을 직접 고르는 구조 | 신규 개발 |
| 7 | **요금제별 엔진 선택** — 프리미엄/베이직/라이트 (#5-4) | 절반 완성. `IMAGE_MODEL` 환경변수 구조가 그대로 티어에 매핑됨 (라이트=3.1 Lite, 프리미엄=3.1 Flash/Pro) | 요청별 분기만 추가하면 됨 |

## 우선순위 제안

### 지금 당장 필요한 것 (B2B 전에도 필요)

#### 1. 피팅 이벤트 로깅 (가장 시급)

대시보드(#5-6)는 데이터가 몇 달치 쌓여야 의미가 있는데, 지금은 피팅할 때마다 아무 기록도 안 남는다.

**제안 구현:**
- `/try-on` 성공 시 Firestore에 한 건씩 저장
- 필드: `userId`, 옷 조합, 카테고리, 모델, 처리시간, 타임스탬프
- 백엔드 몇 줄 수준의 작업
- 나중에 대시보드의 원천 데이터가 됨
- B2B 영업 시 "이미 N건의 피팅 데이터 보유" 근거로 활용 가능

#### 2. 백엔드 인증 (비용 사고 방지 1순위)

현재 `/try-on`이 **인증 없이 완전 공개**라서, URL만 알면 누구나 Gemini 비용으로 무제한 합성 가능하다.  
일일 5회 제한도 앱(AsyncStorage)에만 있어서 서버에서는 막히지 않는다.

**제안 구현:**
- Firebase Auth 토큰 검증
- 서버측 일일 횟수 제한
- B2B 전환 시 테넌트별 API 키·과금 체계로 확장

---

### B2B 전환의 핵심 개발 (Phase 2 목표)

#### 3. 임베드 위젯/스크립트 SDK

기획서 최대 셀링 포인트(74.5%가 연동성 우려)인데 현재 0%.

**필요 작업:**
- 쇼핑몰 상세페이지에 붙는 JS 위젯
- 테넌트(쇼핑몰)별 API 키 체계
- 현재 백엔드는 CORS 전체 허용 + 멀티파트 구조라 API 자체는 재사용 가능
- 위젯 프런트와 키 발급 체계가 새 작업

#### 4. 상품 이미지 자동 추출 파이프라인

**필요 작업:**
- 상세페이지 URL/이미지에서 의류 영역 추출 → 피팅용 데이터 변환
- Gemini 비전으로 "이미지에서 의류 아이템 식별·분류" 전처리
- 추출 결과 캐싱 → 상품당 1회 비용으로 종료

---

### 고도화 (기존 기능 개선)

#### 5. 믹스매치 추천 실구현

**제안 구현:**
- `/get-recommendation` 하드코딩 제거
- 실제 옷장 데이터(Firestore 조회는 이미 존재)를 프롬프트에 반영
- "방금 피팅한 아이템과 어울리는 조합" 반환
- 앱에서 "함께 피팅해보기" 버튼으로 연결
- 백엔드 반나절 수준 작업, 기획서 #5-5 시연 가능

#### 6. 키/몸무게 입력

**제안 구현:**
- 온보딩에 1회 입력 UI 추가
- `/try-on` 프롬프트에 `person is ○cm, ○kg, render realistic fit` 형태로 반영
- 기획서 #4 유저 플로우와 앱 일치

## 추천 착수 순서

```
로깅 → 인증 → 믹스매치 → 키/몸무게 → SDK 위젯 → 자동 추출 → 대시보드
```

앞의 네 가지(로깅, 인증, 믹스매치, 키/몸무게)는 현재 코드베이스에서 바로 착수 가능하다.

# 추가 검토 (2026-07-06): 구현 가능성·비용·트렌드 판단

## 1. 기능 구현 가능성 체크 — 결론: 막히는 것 없음

| 기능 | 판정 | 근거 / 조건 |
|---|---|---|
| 로깅 | 즉시 가능 | 백엔드에 `firebase-admin`(Firestore) 연동 완료, `/try-on`에 requestId·처리시간 로그 존재. 서버 배포만으로 적용 (앱 수정 불필요) |
| 인증 | 가능 (앱 재배포 필요) | 앱이 `@react-native-firebase/auth` 사용 중 → ID 토큰 헤더 전송 + 백엔드 `verifyIdToken()` 검증. 구버전 사용자 보호를 위해 "토큰 없으면 허용+로그만" 과도기 운영 권장 |
| 믹스매치 | 가능 | 옷장 데이터가 `users/{uid}/closet`에 카테고리와 함께 존재. 옷 설명 텍스트가 없으면 저장 시점에 Gemini 비전으로 한 줄 설명 생성(전처리 1회) 필요 |
| 키/몸무게 | 가능 (앱 재배포 필요) | 온보딩 UI + Firestore 프로필 + 프롬프트 반영 |
| SDK 위젯 / 자동 추출 | 가능하나 규모 큼 | 백엔드 재사용 가능. 위젯 JS + API 키 체계는 신규 프로젝트 수준의 일정 필요 |

**주의점:** 결과 이미지가 Storage에 전부 public + 무기한 보관 중.
사용량 증가 시 스토리지 비용 + 프라이버시(얼굴 사진) 이슈가 커지므로,
로깅 작업 시 보관 정책(예: 90일 후 자동 삭제)을 함께 도입할 것.

## 2. 추가 AI 모델 비용

| 기능 | 추가 모델 호출 | 건당 추가 비용 |
|---|---|---|
| 로깅, 인증 | 없음 | 0원 |
| 키/몸무게 (프롬프트 수십 토큰) | 없음 | 사실상 0원 (0.01원 미만) |
| 믹스매치 추천 1회 | 2.5 Flash-Lite 텍스트 1회 | 약 0.3~0.5원 |
| 옷장 아이템 설명 생성 (아이템당 1회, 캐싱) | 2.5 Flash-Lite 비전 1회 | 약 0.5원 |
| 상품 자동 추출 (B2B, 상품당 1회, 캐싱) | 비전 1회 | 약 1원 이하 |

- 신규 기능의 직접 비용은 **피팅 1회 원가(48원)의 1~2% 수준으로 무시 가능**.
- 실질 비용 증가 요인은 믹스매치로 인한 **"함께 피팅" 횟수 증가분** (피팅 +20% → Gemini 비용 +20%).
  이는 engagement 지표와 비례하므로 늘수록 긍정적인 구조.

## 3. 트렌드 기준 판단

### 잘 맞는 부분

- **B2B SDK 피벗 자체가 정답.** B2C 가상 피팅 앱은 전 세계적으로 수익화에 실패해왔고,
  수익은 쇼핑몰 건당 과금 B2B SaaS에서 발생. 카페24 앱스토어 유통 전략도 국내에서 실제 작동하는 채널.
- **"피팅했지만 사지 않은" 데이터는 진짜 차별화 자산.** 쇼핑몰이 어디서도 못 얻는 신호로,
  대시보드가 아니라 데이터 자체가 상품이 될 수 있음. → 로깅 1순위 결론 강화.

### 약하거나 위험한 부분

- **"기술적 혁신"은 해자가 아님.** 합성 엔진이 Gemini API라 경쟁사도 동일하게 구현 가능.
  진짜 방어력은 호스팅사 스토어 선점 속도 + 축적된 피팅 데이터.
  발표 시 기술 자랑보다 "연동 마찰 제로 + 데이터 축적"에 무게 둘 것.
- **반품률 스토리와 실제 기능의 괴리.** 반품 사유 1위는 '사이즈·핏 불만족'인데,
  이미지 합성은 스타일 확인이지 사이즈 확인이 아님.
  이 상태로 "반품 줄여드립니다"로 팔면 도입 후 효과 미달로 이탈 리스크.
  - **보완책:** 키/몸무게 입력을 **사이즈 추천 기능**(신체 치수 × 상품 실측표 매칭, "이 상품은 L 추천")으로 연결.
    AI 비용 거의 없음(룰 기반 + 텍스트 모델), 기획서 핵심 약속을 실체화하는 최고 가성비 투자.

### 수익 관점 보완

- **현재 B2C 광고 모델은 역마진.** 보상형 광고 1회 수익 약 10~40원 vs 피팅 1회 원가 48원.
  광고 충전이 잘 될수록 손해일 수 있는 구조.
  1. B2C는 수익원이 아니라 **B2B 영업용 검증 데이터 생산 채널**로 정의
  2. 헤비유저용 **크레딧 인앱결제** 병행 (예: 10회 1,500원 — 원가 480원 대비 마진 확보)
- **제휴 수수료 라인:** 피팅 결과 공유 이미지에 쇼핑몰 링크 부착 →
  B2B 계약 전에도 만들 수 있는 가장 빠른 수익 라인.
