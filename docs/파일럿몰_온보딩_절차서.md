|---|---|---|---|
| 1 | **쇼핑몰 도메인** | `https://lirin.co.kr` | 이 주소에서만 위젯이 동작하게 잠근다 |
| 2 | **로고 이미지** | PNG, 배경 투명, 가로 500~1000px | 피팅 결과 이미지에 브랜드를 굽는다 |

**임대몰(카페24·고도몰 등)이면 서브도메인을 확인하세요.** 몰마다 주소가 다르므로

## 1. 키 발급 (2분)

터미널에서 아래 두 줄을 실행합니다. **몰마다 새로 만드세요.**

```bash
echo "pk_cdp_$(openssl rand -hex 8)"     # 공개 키
echo "sk_cdp_$(openssl rand -hex 16)"    # 조회 토큰
```

| 키 | 어디에 쓰나 | 누구에게 주나 |
|---|---|---|
| `pk_cdp_...` | 몰 페이지 `<script>` 태그 | **연동 담당자** (페이지에 노출되어도 됨) |
| `sk_cdp_...` | 리포트 조회 | **사장님 본인에게만** |

> 🚫 **`sk_` 를 페이지에 넣으면 안 됩니다.** 그 키로는 매출 데이터가 조회됩니다.
> 연동 담당자에게는 `pk_` 만 전달하세요.

> 🚫 **데모 키(`pk_demo_mall`)를 실제 몰에 쓰면 안 됩니다.**
> 데모 몰 통계에 섞여 리포트가 엉킵니다.

> **접두어가 `pk_cdp_` / `sk_cdp_` 인 이유**
> 흔히 쓰는 `sk_live_` 는 **Stripe 시크릿 키와 같은 형식**이라 GitHub·슬랙 등의
> 시크릿 탐지기가 오탐을 냅니다. 실제로 이 문서를 처음 커밋할 때 GitHub 이
> 푸시를 차단했습니다. 몰에 토큰을 메일로 보낼 때 상대 회사 보안 도구가
> 걸고 넘어지면 곤란하므로 `cdp` 로 바꿨습니다. **되돌리지 마세요.**

발급한 키는 안전한 곳(사내 비밀번호 관리도구)에 몰 이름과 함께 기록해 두세요.
**분실하면 재발급 외에 방법이 없고, 재발급하면 몰이 스크립트를 다시 붙여야 합니다.**

## 2. 고객사 등록 (5분)

Render 대시보드 → `codipop-backend` → **Environment** → `TENANTS` 를 수정합니다.

기존 값에 몰을 하나 추가하는 방식입니다. **JSON 한 줄이므로 쉼표와 중괄호를 조심하세요.**

```json
{
  "lirin": {
    "name": "리린",
    "plan": "starter",
    "tier": "standard",
    "apiKey": "pk_cdp_03e4436d31d07f99",
    "dashboardToken": "sk_cdp_3fe80a2b2fae62e90669b534e00c0adc",
    "origins": ["https://lirin.co.kr", "https://www.lirin.co.kr"],
    "logo": "lirin.png"
  }
}
```

| 항목 | 넣을 값 |
|---|---|
| 맨 앞의 `"lirin"` | 몰 ID. 영문 소문자로 짧게. **한 번 정하면 바꾸지 마세요** (통계가 이 값으로 쌓입니다) |
| `name` | 몰 상호. 위젯 상단과 리포트 제목에 나옵니다 |
| `plan` | `starter` / `pro` / `business` / `enterprise` — 계약한 요금제 |
| `tier` | `standard` 로 두세요. 프리미엄은 ENTERPRISE 협의 건만 |
| `origins` | 받은 도메인. **`www` 유무를 둘 다 넣으세요** — 하나만 넣으면 다른 쪽에서 위젯이 죽습니다 |
| `logo` | 3단계에서 등록할 파일명 |

저장하면 서버가 자동으로 재시작됩니다. **로그에서 이 줄을 확인하세요.**

```
고객사(테넌트) 설정: {"tenants":2,"withApiKey":2,"withDashboardToken":1,...}
```

`tenants` 숫자가 늘지 않았으면 JSON 이 깨진 것입니다. 이 경우 서버는 정상 동작하지만
**새 몰만 무시**되므로 눈치채기 어렵습니다. 반드시 이 줄을 보세요.

> `tier`(화질)와 `plan`(수량)은 다른 항목입니다. 섞지 마세요.

## 3. 로고 등록 (10분 · 개발자 필요)

**이 단계만 코드 배포가 필요합니다.** 영업 혼자서는 안 되고 개발자에게 요청하세요.

1. 받은 로고를 `codipop-backend/public/tenant-logos/lirin.png` 로 저장
2. 커밋 후 푸시 → Render 재배포

**로고 기준:**

| 항목 | 권장 |
|---|---|
| 형식 | PNG (배경 투명) |
| 색 | **흰색 계열** — 반투명 검정 판 위에 얹힙니다 |
| 크기 | 가로 500~1000px |

로고가 없어도 피팅은 정상 동작합니다 (워터마크만 생략). 로고를 못 받았다면
**이 단계를 건너뛰고 나중에 추가**해도 됩니다 — 다만 저장·공유된 이미지에
브랜드가 남지 않으므로 바이럴 효과가 사라집니다.

## 5. 연동 검증 (10분)

몰이 작업을 마쳤다고 하면 **직접 상품 페이지에 들어가서** 아래를 순서대로 확인합니다.

- [ ] 상품 상세에 **착용해 보기** 버튼이 보인다
- [ ] 버튼을 누르면 피팅 창이 뜨고, **상단에 몰 이름**이 나온다
- [ ] 상품 사진과 이름·가격이 맞다
- [ ] 사진을 올리고 피팅하면 **10초 안에** 결과가 나온다
- [ ] 결과 이미지 우하단에 **몰 로고**가 찍혀 있다
- [ ] **이 상품 구매하기**를 누르면 몰의 구매 페이지로 이동한다
- [ ] 리포트에 방금 피팅이 잡힌다 (아래 참조)
- [ ] 리포트의 상품이 코드가 아니라 **상품명**으로 보인다

리포트는 https://codipop-backend.onrender.com/demo/admin.html 에서
**1단계에서 발급한 `sk_` 토큰**을 입력해 엽니다. 이 토큰이 곧 신원이므로
몰 ID 를 따로 넣는 곳은 없고, **다른 몰의 데이터는 열리지 않습니다.**

기간을 `최근 7일`, 최소 피팅 수를 `1회 이상`으로 낮춰야 방금 만든 1건이 보입니다.

**마지막 두 개가 가장 중요합니다.** 앞이 다 되어도 데이터가 안 쌓이면
사장님에게 보여줄 것이 없고, 그게 우리가 파는 것의 전부입니다.

## 6. 사장님 인계

사장님에게 아래 두 가지를 전달합니다. **`sk_` 는 여기서 처음 등장합니다.**

> **리포트 주소:** https://codipop-backend.onrender.com/demo/admin.html
> **조회 토큰:** `sk_cdp_3fe80a2b2fae62e90669b534e00c0adc`
>
> 주소를 여시고 토큰을 한 번 입력하시면 됩니다.
> 사무실 PC 라면 **이 브라우저에 기억**을 체크하시면 다음부터 입력하지 않으셔도 됩니다.
> (매장 공용 PC 라면 체크하지 마세요.)

같이 보면서 **이 세 가지를 짚어 주세요.** 사장님이 리포트를 다시 열게 만드는 것이 여기입니다.

1. **피팅했지만 사지 않은 상품** — 어디서도 얻을 수 없는 데이터라는 점
2. **피팅 → 구매 전환율** — 위젯이 매출에 기여한 증거
3. **이번 달 사용량** — 기본 제공량을 넘겨도 **중단되지 않고** 초과분만 후청구된다는 점

> 3번을 반드시 말로 설명하세요. "한도 초과 = 서비스 중단"으로 오해하면
> 사장님이 이벤트 기간에 위젯을 내려버립니다. **우리 매출이 가장 잘 나오는 시점에.**

## 7. 문제가 생겼을 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 버튼이 안 보인다 | `data-codipop-button` 자리가 없음 | 브라우저 콘솔에 `[CodiPOP] 버튼을 넣을 위치를 찾지 못했습니다` 경고가 뜬다. ② 코드 위치를 다시 안내 |
| 피팅 창이 뜨는데 "허용되지 않은 도메인" | `origins` 에 그 주소가 없음 | `www` 유무, `http`/`https`, 서브도메인 확인 후 `TENANTS` 수정 |
| "등록되지 않은 API 키입니다" | 키 오타 또는 `TENANTS` JSON 깨짐 | 부팅 로그의 `tenants` 숫자 확인 |
| "상품 이미지를 불러오지 못했습니다" | 이미지 주소가 로그인 필요/리다이렉트/이미지 아님 | 그 주소를 브라우저 새 탭에 붙여넣어 이미지가 바로 뜨는지 확인 |
| 로고가 안 찍힌다 | 파일명 불일치 또는 미배포 | 로그의 `⚠️ ...로고를 읽지 못했습니다` 확인 |
| 결과에 글자가 □□ 로 나온다 | **로고 없이 한글 몰명이 들어감** | 로고 이미지를 등록 (3단계) |
| 첫 피팅이 30초 넘게 걸린다 | Render 콜드 스타트 | 시연 전 미리 한 번 호출해 깨워둘 것. Starter 플랜($7/월) 전환 권장 |
| 리포트가 안 열린다 | 토큰 오타 | 사장님 토큰과 `TENANTS` 의 `dashboardToken` 대조 |

## 8. 절대 하지 말 것

| | 왜 |
|---|---|
| `sk_` 토큰을 페이지·메신저 단톡방에 넣기 | 매출 데이터가 조회됩니다 |
| 데모 키(`pk_demo_mall`)를 실제 몰에 쓰기 | 통계가 데모 몰에 섞입니다 |
| 몰 ID 를 나중에 바꾸기 | 이전 통계가 끊깁니다. 복구 방법이 없습니다 |
| `origins` 를 비워두기 | 아무 사이트에서나 그 키로 피팅을 돌릴 수 있습니다 |
| 로고 없이 한글 상호로 워터마크 시도 | 글자가 깨집니다 |

## 10. 지금 구조의 한계 (알고 있을 것)

정직하게 적어 둡니다. 고객사가 늘면 순서대로 문제가 됩니다.

| 한계 | 언제 문제가 되나 | 예정 |
|---|---|---|
| `TENANTS` 가 환경변수 JSON 한 줄 | 10곳 넘으면 사람이 편집하다 깨뜨린다 | Firestore + 관리 화면으로 이전 |
| 로고 등록에 코드 배포 필요 | 몰이 로고를 자주 바꾸면 | 관리 화면에서 업로드 |
| 키 회전(rotate) 수단 없음 | 키가 유출되면 | 재발급 = 몰이 스크립트 재작업 |
| 리포트가 `/demo/` 경로 아래 | 사장님이 "데모"로 인식 | `/dashboard` 로 분리 |
| 조회 토큰 = 사실상 비밀번호 | 사장님이 여러 명이면 | 계정 로그인 도입 |

**첫 3~5곳까지는 지금 구조로 충분합니다.** 그 뒤에 위에서부터 순서대로 고치세요.
